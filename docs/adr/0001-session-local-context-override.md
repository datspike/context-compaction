# ADR-0001: Session-local override для расширенного окна

- Статус: принят
- Дата: 2026-10-09

## Контекст

Registry-запись Pi может объявлять `contextWindow=272000`, хотя у модели есть более высокий capability tier с другой тарификацией. Автоматически использовать такое окно нельзя: это может незаметно перевести обычный запрос на более дорогой pricing tier. При этом пользователю нужен явный режим `/context long-once` или `/context long-chat`, который расширяет окно только в текущей сессии.

Расширение должно сохранить `economy` на точной capability из registry, не менять `models-store.json`, `models.json` и `ctx.modelRegistry`, работать для любых провайдеров и использовать только публичный `pi.setModel()`.

## Решение

1. Точную registry-модель ищем по паре `(provider, id)` текущей модели.
2. Для `economy` используем `min(272000, declared contextWindow)` и не учитываем временный override.
3. Long-режим доступен только при наличии точной registry-записи и явного `cost.tiers` с порогом не ниже объявленной capability.
4. При таком сигнале `/context long-once` получает session-local окно `372000`, а `/context long-chat` — не более `600000`. Источник policy отображается как `session-override`, когда окно действительно расширено.
5. Override применяется через `pi.setModel()` без `persist: true`; глобальные конфигурации и registry не изменяются.
6. После ошибки применения расширение пытается восстановить прежнюю модель через публичный `pi.setModel()`. Если восстановление подтверждено, сохраняется прежний режим; если нет, интерфейс показывает фактическое окно с `source=fallback` и просит повторить выбор `economy`. Частичный отказ проверяется отдельными тестами.
7. Внутренние вызовы `pi.setModel()` защищены от повторной обработки собственного `model_select`, чтобы восстановление не запускало новый переход поверх ещё незавершённой операции.
8. `long-once` возвращается в `economy` только после успешного native compact; `long-chat` сохраняется.

## Рассмотренные альтернативы

- Изменять `models-store.json`, `models.json` или `ctx.modelRegistry`: отклонено, поскольку это глобальное состояние и оно выходит за границы сессии.
- Разрешать long только для `openai`: отклонено, поскольку capability и pricing tier принадлежат registry-записи, а не имени провайдера.
- Разрешать long по одному `contextWindow`: отклонено, поскольку это не подтверждает наличие более дорогого pricing tier и допускает случайное расширение.
- Использовать закрытые методы Pi или напрямую менять внутреннее состояние `AgentSession`: отклонено; расширение опирается только на публичный API.

## Последствия

- Обычный `economy` остаётся консервативным и не меняет стоимость запроса сам по себе.
- Пользователь явно принимает возможную повышенную тарификацию, выбирая long-режим.
- При неудачном публичном переключении восстановление прежней модели зависит от доступности того же API; если восстановление также не подтверждено, расширение сообщает об этом отдельно и предлагает повторно выбрать `economy`.
- Проверки должны покрывать не только capability `272000`, но и записи с более высоким declared capability без `cost.tiers`.

## Нецели

- Изменение глобального каталога моделей или пользовательских настроек Pi.
- Определение физического максимума модели по одному pricing tier.
- Отключение автоматического compact или изменение ядра Pi.
- Выполнение реальных модельных запросов в тестах.

## Проверка

- Policy-тесты проверяют точную registry capability, обязательный pricing-tier gate, session override, `economy` и `off`.
- Integration-тесты проверяют provider-neutral long, отсутствие tier при declared capability `600000`, восстановление после успешного и неуспешного compact, обычный отказ `setModel()` и частичный отказ с восстановлением прежней модели.
- Тестовый макет вызывает `model_select` во время внутренних переходов и проверяет, что recovery не запускает повторный `ensureWindow()`.
- `npm run verify`, `npm pack --dry-run` и `git diff --check` выполняются перед завершением.
