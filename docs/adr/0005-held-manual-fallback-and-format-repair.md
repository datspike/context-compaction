# ADR 0005: стандартная сводка внутри ручного compact и исправление формата append

Статус: принято владельцем 2026-10-17 (пункты 1–4 исправления compact).

## Проблема

Ручной `/compact` удерживает `session_before_compact`, пока служебный ход строит сводку. Вызов `ctx.abort()` отменяет не только ход, но и удерживаемый compact. Новый `ctx.compact()` внутри него заменяет сигнал отмены и создаёт две операции вместо одной. Кроме того, переименование сессии во время стандартной сводки меняет сырой лист ветки, хотя модель не видит новых сообщений.

После перехода на обычный текст append может пропустить раздел ранней части хода. Без отдельной попытки исправления такой ответ сразу требует более дорогой стандартной сводки.

## Решение

Для завершённого невалидного текста ручной путь сначала делает одну попытку исправления на том же префиксе. При повторном отказе стандартная сводка строится из исходной подготовки внутри удерживаемого хука. Pi сохраняет результат исходного compact; второй compact не нужен. Сигнал ручного compact управляет и стандартной сводкой.

Исправление продолжает исходный запрос отклонённым ответом и коротким указанием ошибки. Оно не проходит через пользовательскую ленту. Перед отправкой проверяются префикс, неизменяемый envelope, cache key, владение провайдером, сессия, модель и служебный бюджет. Неизвестный сетевой исход не разрешает стандартную сводку; начатая попытка и неизвестный usage остаются в аудите. Повторных исправлений нет.

Задача прямо указывает, нужна ли ранняя часть хода. Аудит отклонённого ответа хранит только число разделителей и заголовков и наличие обязательных разделов, без текста ответа. Карточка показывает фактическое число исправлений.

Стандартная сводка игнорирует немодельные записи `custom`, `session_info`, `usage`, но сохраняет проверки сообщений, границ, модели и маршрута. Нативный путь использует тот же фильтр немодельных записей.

С момента постановки служебного хода строка работы показывает `Compact: сжимаю контекст (append, кэш)…`. При стандартной сводке она меняется на `Compact: append не прошёл проверку, стандартная сводка…`.

## Исключение и альтернативы

Вызовы инструментов вопреки `tool_choice: "none"` требуют остановить агентский ход: иначе агент может ответить на заблокированные вызовы новым незащищённым запросом. Этот путь по-прежнему отменяет ручной compact и затем запускает отдельный стандартный compact. Расширение не исполняет инструменты. Esc не разрешает fallback или продолжение.

Не выбраны ослабление проверки границы, игнорирование всех изменений сессии, автоматические сетевые повторы и изменение Pi core. Они не нужны для исправления наблюдаемого сбоя и меняют гарантии безопасности.
