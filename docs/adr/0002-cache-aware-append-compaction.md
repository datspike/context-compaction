# ADR-0002: Append compact по умолчанию с неизменным system/tools envelope

- Статус: принят для включения по умолчанию на поддержанном `openai-responses`; остальные модели используют стандартный compact.
- Основание: владелец согласовал append-задачу, включённый кэш, детерминированный хвост, стандартный запасной путь и явно потребовал сохранность исходного system/tools envelope.

## Решение

Для русского режима добавить настройку `contextCompaction.appendCompaction`, по умолчанию `true`. Явное `false` отключает этот путь. Публичные `context_with_system` и `before_provider_request` сохраняют один ограниченный снимок в памяти. История, system и объявления tools не переписываются; задача добавляется одним user message в конец.

Отдельный `modelRegistry.streamSimple` использует `cacheRetention: "short"`, исходный session cache key и `transport: "sse"`. Запрос не участвует в рабочем инструментальном цикле. `toolChoice: "none"` и задача запрещают действия, результат с tool calls не принимается. Новый инструмент compact в каталог не добавляется.

Первая поддержка ограничена `openai-responses` с mid-conversation system messages. Перед сетью `onPayload` проверяет неизменность исходных input prefix, tools, instructions и cache key и добавляет штатную схему Structured Outputs с обязательными `history`/`turnPrefix`. Схема не меняет префикс input. Любое расхождение выбирает существующий summarizer до отправки. Проверка требует настоящего модельного прогона: одинаковый payload и одинаковый prefix ещё не гарантируют cache hit.

Граница сжатия принадлежит подготовке Pi. Свежий хвост не генерируется моделью и его `firstKeptEntryId` не меняется. Несопоставимая с исходным снимком подготовка, недоступный снимок или недостаток объявленного окна выбирают прежний путь. После ответа provenance guard отклоняет summary, если числовой факт найден только в неразрешённом хвосте; это fail-closed защита от смыслового дублирования, допускающая безопасный fallback.

Проверка актуальности сравнивает leaf ветки без метаданных её имени: `session_info` и `custom/pi-autoname-state` не меняют рабочий контекст и не должны отменять оплаченный append-ответ. Все остальные записи, включая неизвестные custom entries, остаются значимыми. Это узкое исключение подтверждено отказом live-запроса при фоновом переименовании; prefix/tools/instructions/cache key, anchor, session и model guards не меняются.

В Pi 1.1.0 `before_agent_start.systemPrompt` применяется после `context_with_system`. Для этого пути снимок запоминает публичный `ctx.getSystemPrompt()` и использует его только после точного совпадения с первым system/developer item реального payload. Заголовок и актуальные tools строятся публичными `createInitialSystemMessage`/`getCurrentTools`, исходные рабочие сообщения не меняются. Проверка prefix/tools/instructions/cache key остаётся до сети; сам mismatch не исправляется заменой полей запроса. Так учитывается реальный forced prompt, а не ослабляется guard ради принятия кандидата. Пока принудительный prompt отличается от исходного системного контекста, чужой текст отвергается независимо от длины, допуска размера и роли первого элемента; следующий точный кандидат ещё может занять снимок. Без принудительной подмены первый элемент точно сверяется с исходным начальным system message, а последующие системные обновления остаются отдельными сообщениями.

Захват `before_provider_request` должен выполняться после преобразователей payload. В полном профиле `pi-codex-image-gen` удалял нативный image tool после захвата, что давало `payload-mismatch/tools` до сети. Для проверенного локального подключения используется явный `extensions` путь после пакетных расширений, без дублирующей записи в `packages`. Это переиспользует порядок загрузки Pi и не копирует чужую фильтрацию. Произвольные поздние преобразования не поддержаны: публичного события с окончательным payload нет, а строгие проверки не ослабляются.

После структурированного ответа с ошибкой формата допускается одна повторная попытка. `invalid-result` и `request-failed` после неё переходят в стандартный русский compact с коротким предупреждением; частичный append-результат не применяется. Успешный append и fallback показывают короткую строку с cache status, длительностью и стоимостью; для pre-send fallback явно указываются `cache not attempted` и `$0.0000`, а stale `context-changed`, отмена и устаревший результат уведомление не вызывают. Обычный штатный compact уведомление не вызывает. Отмена и смена ветки не повторяются. Успех сохраняет суммарный provider usage, включая repair, и число `repairAttempts`; отказ сохраняет доступный usage и число попыток в служебной записи без текста контекста. Английский compact и /tree не меняются.

Для диагностики `payload-mismatch` существующая запись `context-compaction-append` может содержать `payloadMismatch`: фиксированные имена несовпавших полей, индекс первого отличия input и размеры обеих сторон. Тексты, значения cache key, хеши и сами payload не сохраняются. Диагностика не разрешает отправку: существующий guard и стандартный fallback остаются неизменными.

## Границы

Не подразумевается поддержка 1M по одному pricing tier. Structured Outputs и fallback реализуются только для `openai-responses`; `pi-claude-provider` и общий capability-контракт отложены в Q13. Не меняются capability реестра и ядро установленного Pi. Локальная проверка порядка загрузки использует отдельный профиль; переход обычной установки и локальное слияние разрешены отдельным поручением владельца только после доказательства результата и с сохранённым способом возврата. Снимки не пишутся на диск. Не вводятся новые внутренние API Pi или копии provider pipeline.

## Проверка

Немодельные тесты provider payload/schema, хвоста, окна, repair, fallback, provenance, audit provider/model и notification format проходят. Независимая модельная оценка дала ограниченный положительный сигнал качества на сохранённых продолжениях, но лабораторные `cacheRead=0` не блокируют включение: переиспользование кэша проверяется по usage в рабочем Pi. Append включён по умолчанию только для поддержанного `openai-responses`; остальные модели используют стандартный compact. Append без Structured Outputs остаётся отдельной будущей задачей Q13.

Проверка в Pi `1.1.0` подтвердила append success и в изолированном профиле, и с полным набором расширений при позднем явном подключении. В последнем случае сжатие заняло 12.142 с, `repairAttempts=0`, `cacheRead=0`; это доказывает применение, но не экономию. Регрессия с настоящим OpenAI-конвертером без сети отличает ранний захват до фильтра от позднего: первый даёт отказ только по `tools`, второй — success.
