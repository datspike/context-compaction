# ADR 0008: очищенные источники с сохранением исходного кэша

## Context

Goal хранит в продолжениях и служебные команды, и содержательные снимки работы. Для сводки нужен очищенный текст, но append должен сопоставить его с исходным сообщением и сохранить прежний контекст провайдера. Удаление смешанного сообщения теряет решения и доказательства; сохранение целого сообщения не очищает обычный путь.

## Decision

Поддержать необязательное происхождение текстовых custom-сообщений в подготовленных копиях:

```ts
details.compactionProjection = { version: 1, originalContent: originalMessage.content };
```

Обычный суммаризатор использует очищенный content. Append восстанавливает originalContent только для сопоставления с исходным контекстом. В каталог источников он помещает полный очищенный текст с projection: true; для такого источника разрешено использовать только эту цитату, не полное исходное сообщение. Обычные сообщения сохраняют прежние сокращённые цитаты и правила чтения. История и ранняя часть хода остаются раздельными.

Исходный кэш, журнал, payload-проверки, сигналы отмены и бюджет не меняются. Договор ограничен custom-сообщениями со строковым содержимым и версией 1. Неизвестная или некорректная запись не даёт права ссылаться на другое сообщение: действуют прежнее сопоставление и безопасный отказ. Дополнительной зависимости или общего хранилища нет.

## Alternatives

Удаление смешанных сообщений теряет факты. Ограничение только чистыми копиями не решает очистку обычных продолжений. Изменение сохранённого префикса ломает кэш; перенос всех снимков в общие инструкции смешивает границы истории и ранней части хода.

## Consequences

В каталоге появляются полные очищенные цитаты, поэтому его размер иногда вырастет. Это осознанная плата за сохранность фактов без переписывания кэша; прежние проверки размера остаются обязательными. Сокращение служебных команд не доказывает качество сводки или реальную экономию.

## Non-goals

Не менять Pi core, провайдера, контур продолжений, пользовательские настройки и правила разбора модельного ответа. Не переписывать исходные сессии и не переносить бюджеты прежних кампаний.

## Verification

Проверить настоящий генератор Goal с решениями и доказательствами, обе области разрезанного хода, обычный путь и успешный append. Сравнить входы до/после, побайтово сохранить исходный префикс, проверить пустые области и некорректные данные, выполнить verify, pack и diff-check обоих проектов и независимое ревью.

## Status

Принято для совместной реализации, которую владелец явно выбрал после разбора ограничения. Готовность проверяется отдельно.
