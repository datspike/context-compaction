# context-compaction

## Установка

Для установки из публичного Git-репозитория выполните:

```bash
pi install git:github.com/datspike/context-compaction
```

Для локальной разработки и проверки из рабочего дерева выполните:

```bash
pi install -l .
```

Базовая интеграция проверена на Pi `0.87.1`; append после перезапуска требует публичных API реестра провайдеров и границ хода. Живой перезапуск проверен на Pi `1.1.0`, текущие SDK-тесты и изолированный TUI — на `1.3.0`. Расширение не меняет ядро Pi.
Расширение задаёт окно сессии через публичный `pi.setModel()`, регистрирует `checkpoint_compact_continue` и команду `/context`. Подготовка автоматического сжатия остаётся у Pi; поддержанное сжатие служебным ходом передаёт её отдельному служебному ходу. При недоступном служебном ходе используется стандартное сжатие.

## Режимы

```text
/context status
/context economy
/context long-once
/context long-chat
/context off
```

- Базовая возможность и окно `economy` определяются по валидному `contextWindow` точной пары `(provider, id)` из `ctx.modelRegistry`.
- `economy`: применяет `min(272000, declared capability)`. Для окна 272K встроенный механизм Pi с обычным резервом 16K начинает сжатие примерно на 256K.
- При явном выборе `long-once` или `long-chat` расширение может включить session-local override до `600000`, если точная registry-запись уже содержит capability не меньше `272000` и request-wide `cost.tiers` с порогом не ниже этой capability. Это общий сигнал для разных провайдеров, а не список моделей или провайдеров.
- Переопределение окна сессии не изменяет `models-store.json`, `models.json` или `ctx.modelRegistry`; он применяется только через публичный `pi.setModel()` к текущей сессии и показывается как `source=session-override`. Повышенный pricing tier модели при этом остаётся ответственностью явного выбора long-режима.
- `long-once`: применяет `min(372000, effective capability)` и после **успешного** сжатия возвращается в `economy`.
- `long-chat`: применяет `min(600000, effective capability)` и сохраняется после сжатия и возобновления сессии.
- `off`: возвращает окно из реестра и отключает только мягкое ограничение расширения. Он не отключает автоматическое сжатие и восстановление после переполнения Pi: публичного API для отключения этих механизмов нет.
- Если registry-запись не даёт точного long-tier сигнала, long-режим отклоняется, даже когда объявленное окно больше 272K, а расширение оставляет `economy`.
При изменении метаданных через `pi.setModel()` расширение сохраняет текущий уровень рассуждений. Если модель не принимает новое окно, расширение пытается восстановить прежнюю модель. При подтверждённом восстановлении сохраняется прежний режим; если восстановление не подтверждено, показываются фактическое окно и `source=fallback`, а для повторной попытки нужно выбрать `economy`.

Строка состояния:

```text
ctx <tokens>/<window> <percent>% · compact@<threshold|off> · <mode>
```

Порог в строке состояния показывает ожидаемую границу встроенного сжатия Pi при стандартном резерве 16K. Это не отдельное правило расширения.

## Контрольная точка и сжатие контекста

`checkpoint_compact_continue` создаёт `manual-pending`; `ctx.compact()` запускается только на `agent_settled`, когда `ctx.isIdle()`. При ручном сжатии расширение передаёт структурированный журнал как дополнительные инструкции.

При стандартном compact успех подтверждает `session_compact`, а продолжение запускается из `ctx.compact().onComplete` после снятия блокировки Pi. При сжатии служебным ходом исходная подготовка передаётся служебному ходу: продолжение ждёт сохранённой compaction и освобождения этого хода. Контракт `AgentSession.compact()` не подделывается: при передаче управления он сообщает отмену исходной подготовки, а не возвращает результат будущего append.

Перед продолжением проверяются ветка и сессия, последнее настоящее сообщение пользователя и состояние `pi-codex-goal`. `sendUserMessage()` вызывается не более одного раза. Его публичный API не возвращает квитанцию постановки в очередь, поэтому журнал фиксирует вызов, а не гарантированную доставку; неизвестный исход не повторяется автоматически.

Порог и восстановление после переполнения остаются в ведении Pi. Служебный ход использует их подготовку и признак `willRetry`: threshold не создаёт отдельного обычного ответа, overflow возвращается к исходной работе. После успешного сжатия `long-once` возвращается в `economy`.

## Язык сводок

Расширение оставляет сжатие и сводку ветки в ведении Pi. В `ru` оно подставляет русские сводки через `session_before_compact` и `session_before_tree`; в `en` не подменяет их, и Pi использует штатные английские инструкции и формат. Для английского режима задайте в глобальном `<каталог Pi>/settings.json`:

```json
{ "contextCompaction": { "summaryLanguage": "en" } }
```

Допустимы только `ru` и `en`; без настройки используется `ru`. Расширение читает настройку при загрузке из `PI_CODING_AGENT_DIR` или `~/.pi/agent`; после изменения перезапустите Pi или выполните `/reload`. Неверное значение отклоняется при загрузке, а не превращается незаметно в другой язык. Установщик `pi-opinionated` настраивает это поле вместе с языком профиля; расширение можно использовать и отдельно.

При `en` обработчик `session_before_compact` сохраняет учёт операций, но не возвращает свою сводку; обработчик `session_before_tree` не регистрируется. `/context`, журнал аудита и `checkpoint_compact_continue` остаются доступны, а дополнительные инструкции ручной контрольной точки и сообщения расширения используют английский язык. Для новых английских сессий сводки compact, разрезанного хода и `/tree` создаёт штатный Pi; расширение не дублирует их алгоритм и не переводит сохранённые сводки.

При переключении существующей русской сессии штатный Pi может оставить текст прежней русской сводки в контексте разрезанного хода. Кроме того, при переходе с созданной расширением сводки на штатную Pi не переносит её накопительные `readFiles`/`modifiedFiles` из `details` в новый учёт файлов. Для полностью английской истории и непрерывного учёта файлов начните новую сессию. В `ru` расширение сохраняет подготовку разрезанного хода и полный накопительный учёт в метаданных. При ошибке генерации Pi использует штатный механизм сводки: ограничение файловых наводок в этом случае не применяется, а прежние метаданные остаются в исходных записях сессии.

### Cache-aware append compact

В русском режиме append compact включён по умолчанию для поддержанного `openai-responses`. Его можно отключить в глобальном `<каталог Pi>/settings.json`:

```json
{ "contextCompaction": { "summaryLanguage": "ru", "appendCompaction": false } }
```

Append запускает отдельный служебный пользовательский ход через штатную цепочку Pi. Поэтому он работает после перезапуска той же сессии без промежуточного обычного модельного запроса и без сохранённого на диске снимка payload. Единый путь используется для `/compact`, `checkpoint_compact_continue`, threshold и overflow.

Поддерживается `openai-responses` с явно объявленной поддержкой системных сообщений посреди истории и публичным доступом к провайдеру через реестр Pi. Если среда выполнения не поддержана или не хватает окна, расширение выбирает стандартный русский compact. Английский режим и `/tree` не переводятся на native append; другие провайдеры и вариант без Structured Outputs сюда не входят.

Перед отправкой штатные преобразования Pi формируют актуальные системные сообщения, объявления инструментов и контекст. К истории добавляется задача сводки с исходными границами, а временная делегирующая обёртка провайдера проверяет окончательный payload после цепочки `onPayload`. Structured Outputs требует строковые `history` и `turnPrefix`, `strict: true` и `additionalProperties: false`. Префикс `input`, системные инструкции, модель и cache key проверяются перед отправкой. Окончательные `tools` и `include` могут дополнять штатные обработчики: они передаются провайдеру без замены, а не сравниваются с промежуточным состоянием до этих обработчиков.

Служебный запрос устанавливает `tool_choice: "none"` и лимит ответа. Любой tool call отклоняется, а отдельный обработчик блокирует исполнение инструментов. Используется SSE без `previous_response_id`, без повторных попыток провайдера и с ограничением времени. Текущий запрос ограничен 16 MiB сериализованного JSON и хранится только в памяти.

Pi выбирает `firstKeptEntryId` и свежий хвост; расширение не сдвигает эту границу. Общие проверки отклоняют неверный JSON, неподходящие заголовки, tool calls и числовые факты, пришедшие только из сохраняемого хвоста. Служебный ход не повторяет неудачный запрос для исправления ответа: при допустимом отказе он переходит на стандартный русский compact. Abort, смена ветки/сессии/модели и неизвестный исход не разрешают повторную отправку или применение старой сводки.

При восстановлении `overflow` стандартная сводка строится из исходной подготовки и сохраняется через `turn_end`, а не через новый ручной compact. Это сохраняет исходную причину и позволяет продолжить прерванную работу ровно один раз. Для ответа с ошибкой, который завершает цикл Pi, `agent_before_settle` разрешает продолжение только после подтверждения сохранённой границы. Отмена, смена источника, сессии или модели и отклонённая граница не разрешают продолжение.

При отмене до начала служебного хода, в том числе перед переходом `/tree`, контроллер освобождается без ожидания отсутствующего `turn_end`. У `sendUserMessage()` нет квитанции постановки: если Pi отклонил вызов до начала хода, расширение не получает отдельного события отказа и не повторяет запрос автоматически. Следующий compact отменяет и освобождает такую ожидающую операцию; после этого compact можно вызвать снова без reload.

Служебные сообщения узнаются по UUID и соответствующей записи `context-compaction-native`. Они не считаются настоящим пользовательским запросом и исключаются из контекста продолжения через новые записи `context_edit` без перезаписи истории, включая оставшийся после прерывания ход. Исходный JSONL не переписывается; системные сообщения при очистке сохраняются.

Сводка сначала предлагается на границе хода вместе с очисткой. Успех, аудит и карточка подтверждаются только после обнаружения реально сохранённой compaction. Если другой обработчик отклоняет границу, записывается `outcome: "unknown"`, `reason: "apply-failed"`, а не ложный успех. Изменение метаданных сессии само по себе не делает результат устаревшим; новая переписка, другая ветка, сессия или модель — делают.

После сохранённого compact появляется постоянная карточка `context-compaction-card`, не попадающая в контекст модели. Например: `◆ append compact · cache hit 92% · 258.8k → summary ~4.1k · 12.3 s · $0.0208`; при fallback: `◆ standard compact · append fallback (insufficient-window) · …`. Ctrl+O раскрывает триггер, модель, cache read/input, время и стоимость. Размер summary приблизительный и не включает сохранённый хвост. Карточка хранит числа и имена, не prompt или payload.

В TUI исходный `/compact` может показать `Compaction cancelled` перед служебным ходом: это передача управления, а не результат append. Окончательный результат отражает карточка. В проверенном Pi `1.3.0` служебный запрос и JSON-ответ могут оставаться видимыми в ленте, хотя удалены из модельной проекции; это ограничение отображения, не дополнительный пользовательский запрос.

`context-compaction-append` сохраняет outcome, duration, usage, cache status и безопасный `appendAttempt` с фазами `preflight`, `provider`, `parse`, `apply`. Ошибки содержат классы и размеры, но не исходный ответ, prompt, payload или cache key. Для начатой попытки без подтверждённого usage стоимость и cache status остаются неизвестными; `aborted` не превращается в нулевой cache miss. При fallback расход append и последующего standard compact учитывается раздельно.

Cache hit и экономия не следуют из успешного append. Их надо подтверждать фактическими usage и задержкой при правильном продолжении; `cacheRead=0` не доказывает потерю кэша после рестарта. Объявленные 272K нельзя расширять до 1M по одному pricing tier или виртуальному окну.

### Файловые наводки

Смысловая часть сводки сохраняет цель, решения, ограничения, критерии завершения и достаточности и незавершённую работу. Важные для продолжения точные пути должны оставаться в этом тексте. Расширение не обрезает его ради ограничения файлового списка.

В русском режиме вместо полного перечня файлов добавляется блок `<file-hints>` длиной не более 6000 символов JavaScript (`String.length`, не токенов). Он содержит до 24 точных наводок, сгруппированных по папкам: сначала пути, упомянутые в смысловом тексте, затем недавно затронутые прямыми вызовами `read`, `write` и `edit`. До восьми групп показывают размер остальной истории. Корни разных рабочих деревьев не объединяются, длинные пути не обрезаются, а имена экранируются как JSON-строки.

Полные списки остаются в `details.readFiles` и `details.modifiedFiles` каждой созданной расширением записи. Это журнал наблюдавшихся обращений, а не текущий Git diff: он не доказывает успешность операции и не охватывает все изменения через командную оболочку, составные инструменты или другие процессы. Наводки не являются списком обязательных повторных чтений.

При следующем сжатии прежние файловые блоки убираются из входных сводок; смысловой текст, пользовательские сообщения и результаты инструментов не сокращаются этой обработкой. Блоки внутри ограждённых примеров кода и незавершённые файловые блоки сохраняются. Строки внутри завершённого файлового блока считаются данными журнала: в старом формате имена файлов не экранировались и могут напоминать разметку. Если имя совпадает с закрывающим тегом, граница блока сверяется с точными списками в метаданных. Без этих списков неоднозначную границу старого формата надёжно восстановить нельзя. Для `/tree` очистка выполняется до отбора истории по размеру, а исходные записи и их метаданные не меняются.

Для возвращения к прежним решениям используйте доступный поиск истории, например `session_search`/`session_get`, если они установлены. Полный файловый журнал можно прочитать в `details` соответствующей записи JSONL; расширение не добавляет новый поисковый инструмент и не требует Hermes. Старые сессии не переписываются. Английский режим и штатная генерация Pi остаются без изменений.

## Журнал сессии

Расширение добавляет записи типа `custom`, в которые данные только дописываются:

- `context-compaction-mode` с именованным режимом;
- `context-compaction-audit` версии 2: correlation, origin, reason, phase, tokens, window, threshold, mode, source, `willRetry` и зафиксированные идентификаторы сессии и ветки (`sessionId`, `tree`).

Журнал аудита не содержит `summary`, текста сессии, содержимого вызовов инструментов, необработанных ошибок, данных авторизации и окружения, PID или путей. Старые `checkpoint-compact-session-threshold` только обнаруживаются, игнорируются и один раз показывают уведомление; они не переписываются.

## Проверка

```bash
# Выполняйте команду из корня репозитория
npm run verify
```

`verify` использует набор зависимостей текущего `pi` и проверяет типы локальным TypeScript из `devDependencies`. Если `pi` запускается через оболочку-обёртку, задайте `PI_RUNTIME_FINAL_CLI` для фактического исполняемого файла Pi; поиск пути не выполняется для другого `pi` в `PATH`.

## Для участников

Перед отправкой изменений запустите `npm run verify` и проверьте Git-установку из отдельного чистого каталога Pi. Не добавляйте `node_modules`, `.env`, локальные артефакты окружения и временные файлы. Изменения поведения должны опираться на публичные API Pi; закрытые обходы внутреннего runtime и подмена методов во время выполнения в проекте не принимаются.

Переносимый рабочий процесс и границы публичных/локальных данных: [docs/workflows.md](docs/workflows.md). Приватные планы и результаты модельных экспериментов не входят в Git и публикуемый пакет.
