# context-compaction

## Установка

В корне репозитория выполните:

```bash
pi install -l .
```

Расширение проверено на Pi `0.87.1`. Оно использует публичные хуки Pi и не меняет ядро Pi.
Расширение задаёт локальное для сессии окно контекста через публичный `pi.setModel()`, регистрирует `checkpoint_compact_continue` и команду `/context`. Pi `0.87.1` сам выполняет автоматическое сжатие контекста, обрабатывает результат и продолжает запуск агента; расширение не изменяет внутренний код Pi и не отменяет встроенное сжатие.

## Режимы

```text
/context status
/context economy
/context long-once
/context long-chat
/context off
```

- Возможность определяется только по валидному `contextWindow` точной пары `(provider, id)` из `ctx.modelRegistry`.
- `economy`: применяет `min(272000, declared capability)`. Для окна 272K встроенный механизм Pi с обычным резервом 16K начинает сжатие примерно на 256K.
- `long-once`: доступен только при увеличении окна сверх `economy`; применяет `min(372000, capability)` и после **успешного** сжатия возвращается в `economy`.
- `long-chat`: доступен на том же условии; применяет `min(600000, capability)` и сохраняется после сжатия и возобновления сессии.
- `off`: возвращает окно из реестра и отключает только мягкое ограничение расширения. Он не отключает автоматическое сжатие и восстановление после переполнения Pi: публичного API для отключения этих механизмов нет.

При изменении метаданных через `pi.setModel()` расширение сохраняет текущий уровень рассуждений. Если модель не принимает новое окно, режим откатывается к `economy` и появляется уведомление.

Строка состояния:

```text
ctx <tokens>/<window> <percent>% · compact@<threshold|off> · <mode>
```

Порог в строке состояния показывает ожидаемую границу встроенного сжатия Pi при стандартном резерве 16K. Это не отдельное правило расширения.

## Контрольная точка и сжатие контекста

`checkpoint_compact_continue` создаёт `manual-pending`; `ctx.compact()` запускается только на `agent_settled`, когда `ctx.isIdle()`. При ручном сжатии расширение передаёт структурированный журнал как дополнительные инструкции.

После подтверждения `session_compact` расширение только отмечает успех. Продолжение ручной контрольной точки запускается из `ctx.compact().onComplete`, когда Pi уже снял внутреннюю блокировку сжатия; до этого `sendUserMessage()` отклоняется. Перед вызовом проверяются ветка и сессия, метка последнего настоящего сообщения пользователя и состояние `pi-codex-goal`.

Контракт: `sendUserMessage()` вызывается не более одного раза. Публичный `ExtensionAPI.sendUserMessage()` не возвращает квитанцию постановки в очередь, поэтому расширение не может отличить принятую очередь от ошибки, которую Pi передаёт обработчику ошибок. Журнал аудита фиксирует один вызов после снятия блокировки и не выполняет повторный запуск.

Автоматический порог, обычная команда `/compact` и восстановление после переполнения принадлежат Pi. Расширение только пишет журнал аудита и откатывает режим `long-once` после успешного `session_compact`; оно не создаёт искусственное продолжение и не запускает повторную попытку после `session_compact_failed`.

## Язык сводок

Расширение использует встроенное сжатие и сводку ветки Pi через публичные обработчики `session_before_compact` и `session_before_tree`. Естественный текст сводки запрашивается на русском языке, а фиксированные заголовки нормализуются в русские названия без изменения путей, команд, идентификаторов, сообщений ошибок и машиночитаемых блоков.

Для обычного сжатия расширение сохраняет подготовку разрезанного хода и накопительный учёт файлов. Для `/tree` сохраняются `readFiles`, `modifiedFiles` и `usage`. Если русская генерация недоступна или завершается ошибкой, обработчик возвращает `undefined`, и Pi использует штатный механизм сводки.

Публичный `SessionBeforeTreeEvent` не отдаёт настройку `branchSummary.reserveTokens`, поэтому расширение использует встроенное значение по умолчанию `16384`. При нестандартном значении встроенный механизм может выбрать другой объём истории для `/tree`.

## Журнал сессии

Расширение добавляет записи типа `custom`, в которые данные только дописываются:

- `context-compaction-mode` с именованным режимом;
- `context-compaction-audit` версии 2: correlation, origin, reason, phase, tokens, window, threshold, mode, source, `willRetry` и захваченный session/tree.

Журнал аудита не содержит `summary`, текста сессии, содержимого вызовов инструментов, необработанных ошибок, данных авторизации и окружения, PID или путей. Старые `checkpoint-compact-session-threshold` только обнаруживаются, игнорируются и один раз показывают уведомление; они не переписываются.

## Проверка

```bash
# Выполняйте команду из корня репозитория
npm run verify
```

`verify` использует набор зависимостей текущего `pi` и проверяет типы локальным TypeScript из `devDependencies`. Если `pi` запускается через оболочку-обёртку, задайте `PI_RUNTIME_FINAL_CLI` для фактического исполняемого файла Pi; поиск пути не выполняется для другого `pi` в `PATH`.

## Для участников

Перед отправкой изменений запустите `npm run verify`. Не добавляйте `node_modules`, `.env`, локальные артефакты окружения и временные файлы. Изменения поведения должны опираться на публичные API Pi; закрытые обходы внутреннего runtime и подмена методов во время выполнения в проекте не принимаются.
